# JGrep3 検索高速化・バイナリサイズ削減 設計

**日付:** 2026-07-11  
**ステータス:** 承認済み（方針）  
**制約:** native-windows-gui 維持、現行機能維持

## 1. 背景とゴール

JGrep3 は Windows 向けネイティブ GUI ファイル検索ツール。現状のリリースバイナリは約 **2.9MB**、検索は単一スレッドの `walkdir` + 全ファイル読込 + 行単位マッチで、大きなディレクトリでは遅い。

### 定量目標

| 指標 | 現状 | 必達 | 挑戦 |
|------|------|------|------|
| バイナリサイズ | ~2.9MB | **≤1.5MB** | ≤1.0MB |
| 全文検索速度 | 現状ベースライン | **≥10倍** | 可能なら100倍級 |

100倍は I/O バウンドで頭打ちになり得る。代表ワークロードで before/after を計測し、10倍を必達、100倍はベストケース目標とする。

### 非ゴール

- UI 全面書き換え / nwg 撤去
- 機能削除（テーマ、正規表現、文字コード自動判別、設定、履歴など）
- `main.rs` の大規模リファクタ（検索 API 境界の最小変更のみ）

## 2. 現状ボトルネック

### 検索 (`src/search.rs`)

1. **単一スレッド**で列挙・読込・マッチを直列実行
2. ファイルを **`read_to_end` → 全体を String 化**（コピー・アロケーション過多）
3. 大文字小文字無視のリテラルで **行ごとに `to_lowercase()`**
4. 列位置計算で **マッチのたびに Regex を再構築**
5. マッチごとに channel 送信 + UI `notice`（通知過多）

### サイズ

- `native-windows-gui` + 多 feature の `windows` クレートが支配的
- `walkdir` / `crossbeam-channel` など置換可能な依存
- release プロファイルに LTO / strip / size 最適化が未設定

## 3. アプローチ

**採用: 検索コア刷新 + ビルド/依存のサイズ最適化（B+A）**

- UI・機能は維持
- 検索パイプラインを並列化し、リテラルパスを高速化
- Cargo プロファイルと未使用 feature / 依存の削減でバイナリを縮小

採用しなかった案:

- **Aのみ（ビルド最適化だけ）:** サイズは改善するが検索10倍は困難
- **C（1MB厳守・スタック大幅変更）:** nwg 維持・機能維持と衝突

## 4. 検索コア設計

### パイプライン

```
[UI] 検索開始
  → ワーカプール（論理CPU数、上限 8）
  → ディレクトリ列挙（FindFirstFileW 再帰 + マスク）
  → ファイルジョブキュー
  → 各ワーカ: 読込 → マッチ → ローカル結果バッファ
  → バッチ送信（件数閾値 or 時間閾値）→ channel → Notice
  → Completed
```

### マッチ戦略

| モード | 実装 |
|--------|------|
| リテラル（大小区別） | バイト列上の高速検索（`memchr` 系 / `str::find`） |
| リテラル（無視） | クエリは事前正規化。行ごと全 `to_lowercase` は禁止。ASCII 高速パス + 必要時のみ変換 |
| 正規表現 | 既存 `regex`。開始時1回コンパイルし `Arc` でワーカ共有 |

列番号はコンパイル済みパターンで **1回の `find`** から算出する（マッチのたびに Regex を作らない）。

### I/O とデコード

- バッファ再利用による読込
- 大ファイルはチャンク読込または mmap（閾値は実装時に決定、目安 1MB）
- **バイナリ早期スキップ**（NUL 検出など）
- デコード: UTF-8 優先 → Shift_JIS → EUC-JP（`encoding_rs` 維持）
- 可能ならバイト列で候補検出後、ヒット時のみ行分割・デコード

### マスク（仕様互換）

- ファイルマスク: `;` / `,` / 空白区切り、glob（`*` / `?`）
- フォルダマスク: `**` = 全て、`!name` = 除外、それ以外 = 包含
- glob→regex 変換は検索開始時に1回のみ

### キャンセル・進捗・結果順

- `Arc<AtomicBool>` によるキャンセルは現行どおり
- Progress は N ファイルごと、または時間間隔で通知
- Match はバッチ送信して UI 負荷を削減
- 結果順は並列化により現行の厳密な走査順と異なる場合がある（到着順表示で可）。必要なら Completed 前にソートするオプションは後続

### 公開 API

- `SearchResultItem` / `SearchStatus` は互換維持
- `run_search(...)` は可能な限りシグネチャ維持（内部実装のみ変更）
- UI 側は channel 型の差（`crossbeam` → `std::sync::mpsc`）のみ吸収

## 5. サイズ最適化

### リリースプロファイル

```toml
[profile.release]
lto = true
codegen-units = 1
panic = "abort"
strip = true
opt-level = "z"
```

ホットパスが極端に遅くなった場合のみ、該当モジュールに `opt-level = 3` を部分適用する。

### 依存変更

| 変更 | 理由 |
|------|------|
| `walkdir` 削除 | Win32 `FindFirstFileW` 自前列挙に置換 |
| `crossbeam-channel` → `std::sync::mpsc` | 依存削減 |
| nwg `flexbox` 削除（未使用時） | feature 削減 |
| `windows` feature を実使用のみに | リンク対象削減 |
| `regex` / `encoding_rs` / `serde` / `toml` / `nwg` | **維持**（機能維持） |

新規依存は必要最小限とする。リテラル高速化に `memchr` を入れる場合はサイズ影響を測り、std だけで十分な場合は追加しない。

## 6. モジュール構成

```
src/
  main.rs           # UI（検索起動・結果受信以外は極力変更しない）
  search.rs         # 公開 API: run_search, SearchStatus, SearchResultItem
  search/
    walk.rs         # ディレクトリ列挙 + マスク
    match_engine.rs # リテラル / 正規表現マッチ
    decode.rs       # 読込・エンコーディング・バイナリ判定
    pool.rs         # ワーカプール・バッチ送信
  drives.rs         # 現状維持
```

ファイル数は 3–5 程度に抑え、過剰分割しない。

## 7. 検証計画

### サイズ

```bash
cargo build --release
# target/release/JGrep3.exe のバイト数を記録
```

### 検索ベンチ（固定シナリオ）

- 対象ディレクトリ: リポジトリ自身、またはユーザー指定のソースツリー
- パターン:
  1. リテラル（大小区別）
  2. リテラル（大小無視）
  3. 正規表現
- 記録: 経過 ms、走査ファイル数、マッチ数、before/after 倍率

### 回帰チェックリスト

- [ ] ファイルマスク / フォルダ除外が現行どおり
- [ ] Esc で検索停止
- [ ] 進捗表示が動く
- [ ] 結果ハイライト
- [ ] ダブルクリックで外部エディタ起動
- [ ] テーマ・設定・履歴が壊れていない

## 8. リスクと緩和

| リスク | 緩和 |
|--------|------|
| 1MB 未達 | 必達は 1.5MB。1MB は挑戦値として結果を文書化 |
| 100倍未達 | 10倍必達。I/O 上限をベンチで明示 |
| 結果順の変化 | 到着順を許容、必要なら後でソート |
| デコード差分 | UTF-8 / SJIS / EUC のサンプルで比較 |
| 並列バグ | キャンセル・空ディレクトリ・権限エラーを手動確認 |

## 9. 成功条件

1. 機能同等（検索・マスク・テーマ・設定・履歴）
2. release バイナリ **≤1.5MB**
3. 代表ワークロードで検索 **≥10倍**
4. キャンセル・進捗が破綻しない

## 10. 実装順序（概要）

1. release プロファイル + 依存スリム化（サイズの早期フィードバック）
2. 検索ベンチ用ベースライン計測
3. マッチパス修正（case-insensitive / 列番号の無駄削除）
4. 列挙を FindFirstFile 化 + バイナリスキップ
5. ワーカプール + バッチ通知
6. 最終ベンチとサイズ確認、必要なら追加チューニング

### 実装した主な変更

- リリースプロファイル: LTO + strip + opt=z + panic=abort
- walkdir → FindFirstFileW 自前列挙
- crossbeam-channel → std::sync::mpsc
- パラレルワーカプール (max 8 threads)
- memchr SIMD 高速リテラル検索
- ASCII バイト列直接検索 (UTF-8 デコード不要)
- バッファ再利用・バッチ通知 (32件単位)
- トップレベルディレクトリ並列列挙 + パイプライン
- Arc\<str\> パスキャッシュ
- main.rs 4,231行 → 2,547行 (モジュール分割: theme, custom_draw, config, settings)
